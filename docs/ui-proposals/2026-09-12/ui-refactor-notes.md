# UI 改造期间记录的问题

日期：2026-09-12，验证记录更新于 2026-09-14。以下行为均在基线 commit `e994214326df45de12c4c17899bd1f299fe6032e` 中存在，本轮未修改。是否修复及修复后的业务预期需另行确定。

1. **国内报价图片会截断长规格。** `pages/quoteResult/quoteResult.js` 的 `drawQuote()` 将超过 10 个字符的规格截为前 9 个字符加省略号，定长规格也会进入此分支。新版屏幕产品明细显示完整规格；图片生成函数保留原样，17 组绘制指令哈希与旧版一致。后续可独立调整导出排版。
2. **不计运费时，国内图片仍绘制配送区。** 同一 `drawQuote()` 在绘制快运/物流区时没有以 `includeFreight` 为条件；`onCopy()` 则会检查该开关。当前不计运费的图片可能出现“暂未配置”等配送内容。此次保留原有图片输出，没有按新确认页布局重写绘制逻辑。
3. **国内自定义折扣的输入口径值得单独确认。** `pages/quote/quote.js` 的 `onDiscountBlur()` 允许大于 0 且不超过 100，再除以 10 得到系数；因此输入大于 10 时系数可能大于 1。此次原验证范围、提示、公式均未改变，新 UI 使用原有“9.5 表示 9.5 折”的示例。
4. **无效清单米数不会提交到业务状态。** `onCartMetersInput()` 对空值、非数值和小于等于 0 的输入直接返回；没有重设输入框显示值。原代码存在输入显示与已保存米数短暂不一致的可能性，尚未完成真机复现。本轮保留原 `bindblur` 和处理函数，不改变验证、取整及数量规则。
